Try a C website with Umicom Web Studio

The local service example connects Framework's native listener to its C route handlers. It provides a C-authored website/API sample and a read-only preview of a selected small website export. Its server runs in a terminal separately from the visual creative workspace.

  1. After building Web Studio, open a terminal in the installed executable directory.
  2. Start umicom-web-studio-local-service --port 8080. It should print the local browser address.
  3. Open http://127.0.0.1:8080/ in a browser. Use the health link to inspect a JSON response.
  4. Enter text in the form and send it. The C echo handler returns the form-encoded request body as plain text. Use the browser Back action to return to the form.
  5. Press Ctrl+C in the terminal to stop. Allow any active request to finish its bounded wait.

If the port is already occupied, select another port such as 8081. If a page cannot load, check that the executable is still running and that the browser address uses the same port. The service binds only to your own computer.

Preview exported pages

  1. Export your website into a separate folder with index.html at its top level. Include only files intended for the browser.
  2. Stop the demo service, then run:
umicom-web-studio-local-service --port 8080 --root "C:\Sites\MyExport"

Replace that path with your absolute export folder. The service now serves the selected files, with no demo routes. Requests ending in a slash select that folder's index page. Each file must be at most 16,383 bytes. HTTP 413 means it is too large; 404 means the requested file is absent; 403 means its path is refused. File and directory links are refused, and no directory listing or upload is provided.

To view another export, stop the service and restart with its root. The service reads files without writing them. Do not select your source checkout or a folder containing keys or personal documents. Browser requests must use the printed local address: requests from unrelated website origins are refused before reading files.

Develop a route

The complete example source is framework/examples/web/local_service.c in the Applications checkout. Extend its route table and callbacks to study C-authored HTML and JSON. Framework owns byte framing, partial sends, deadlines and connection closure. Product handlers should call reusable Framework domain services instead of embedding duplicated application logic.

Current scope

This sample serves a demo website, a health response and a text echo, or a selected folder of small exported files. It does not import assets into the designer, authenticate users, handle payments or broker orders, provide TLS, or qualify mobile/WebAssembly builds. It handles one small HTTP/1.1 request per connection and closes afterward. Native request bytes are limited to 16 KiB; upload and streaming services need their own larger, reviewed storage and transport workflow.

Use the Framework learning guide A local website and API in C for the complete service ownership and protocol limits. C remains the reusable implementation language; this example does not require Wt or C++.
